### Reported large-patch performance issue

After deployment, the user reports that playing Neon chorus and zooming causes audible pauses and visible zoom jitter. **Keep the complete 38-module example** as the scale/performance reference. The original functional checks above did not establish smooth sustained navigation on the user's device. The first local fixes and measurements are documented at the top of this file; physical-device verification remains open.

Initial source inspection shows that transport ticks update React state at the app root, while every camera change renders the Workspace and its complete ModuleCard trees. Every card receives the tick and drum-step props, including modules without playback indicators, and camera movement updates each panel's position/scale separately. `useWorkspaceGestures` publishes a state change for every movement event. The audio look-ahead scheduler also uses the browser's main thread, so long rendering/painting work is a plausible cause of missed scheduling windows; this is a lead rather than a measured diagnosis. Cable shadows and detailed panel finishes add painting work and should be measured before changing their appearance.

Next performance work should profile playback plus sustained zoom/pan with this exact example, measure long frames and audio scheduling gaps, isolate transport indicators from static controls, keep camera movement from re-rendering complete instruments, and coalesce gesture updates to display frames. Preserve all modules, routing, sound, tactile finishes, keyboard/touch access and saving. Verify on the affected physical device as well as under browser CPU pressure before claiming the pauses are fixed.

## Known boundaries

- The source and history are hosted on GitHub, and production runs on Cloudflare Workers. A separate private Sites project was registered earlier, but source synchronization/publication to Sites was blocked by automatic approval review because that upload was not explicitly authorized. No Sites version has been published. Obtain explicit user authorization before retrying that separate upload.

- Local-first, single-user storage. No accounts or cloud database; static hosted copies use browser storage. The Node server remains local and unauthenticated.
- The melodic sequencer has eight steps; drum patterns have sixteen sixteenths. Keyboard voices are monophonic with last-note priority and chromatic pitch. No physical MIDI support.
- Eight-step melodic and sixteen-step drum patterns; time signature controls beat grouping rather than pattern length. 6/8 currently uses three quarter-note groups, not a compound-meter transport.
- Capture uses native MediaRecorder audio (WebM/Ogg/MP4 depending on browser), with WAV, MP3 and Original downloads. Recording takes are capped at 10 minutes; conversion preserves the captured quality rather than recovering lost detail. Rendering a patch faster than real time is not implemented.
- Entire module graph rebuilds when routing changes, which may make a small transient. Parameter/position edits keep the existing graph.
- Noise and reverb are generated anew for each graph, so their exact texture is not deterministic between sessions.
- Background tab throttling can interrupt browser audio scheduling.
- Responsive canvas scrolls/pans on narrow screens; a full hardware rack remains larger than a phone viewport.
